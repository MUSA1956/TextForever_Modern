# TextForever Modern

把一堆按章节拆开的 `.txt` 小说，按章节顺序合并成一个大的 `.txt`。
是 [TextForever] 那个老软件的现代替代品，**当前只做合并这一件事**。

- **纯本地**：文件只在你自己的浏览器里读，不上传、不联网。
- **零安装**：不用装 Python、不用装 Node、不用 `npm install`。
- **可搬走**：整个文件夹复制到另一台电脑，双击 `index.html` 就能用。

---

## 一、怎么用

有三种方式，选一种：

| 方式 | 操作 | 拖放 | 前提 |
|---|---|---|---|
| **A. 启动.bat（推荐）** | 双击 `启动.bat`，浏览器会自动打开 `http://127.0.0.1:8765` | 正常 | 本机有 Python 3（只用自带标准库） |
| A2. 启动_GBK.bat | 同上，黑窗口提示为中文；文件是 GBK 编码，在 UTF-8 编辑器里打开会显示乱码（不影响运行） | 正常 | 同上 |
| B. 直接开网页 | 双击 `index.html`（走 `file://`） | 部分浏览器受限 | 无 |

> 两个启动器只能开一个（都要占用 8765 端口）。

> 2026-11-19 实测：**Tabbit 在 `file://` 下拖放拿不到文件**，同一个页面改用 `http://127.0.0.1` 就正常。所以拖不进来时，要么用「选择文件夹」（一定可用），要么双击 `启动.bat`。

1. 点「选择文件夹」挑章节目录，或者把文件夹 / 多个 txt 直接拖进虚线框。
   - 子文件夹会自动递归；
   - 只收 `.txt`，其他文件会被跳过并提示数量。
2. 检查列表里的顺序，以及「识别章节号」「编码」两列：
   - 顺序不对：改「排序」规则，或点 ↑ ↓ 手动调；
   - 编码认错：在这一行的下拉框里手动指定。
3. 选输出编码（默认 UTF-8 无 BOM）和换行（默认 CRLF），按需要勾选或取消「加标题」「章节之间空一行」。
4. 点「合并并导出」，选保存位置。

> 浏览器不允许网页原地覆盖你的源文件，所以导出永远是"另存一份"。
> 关闭 `启动.bat` 的黑窗口 = 停止本地服务；它只监听 `127.0.0.1`，局域网和外网都连不进来。

## 二、输出长什么样

默认两个开关都开着：每一章开头是**文件名（去掉 `.txt`）**，章与章之间空一行：

```
第一章 初入江湖

（这一章的正文，原样保留）

第二章 夜雨

（这一章的正文）
```

结构由两个开关控制：

| 开关 | 默认 | 作用 |
|---|---|---|
| 在每章开头添加文件名作为标题 | 开 | 关掉后不插入文件名——适合正文里本来就写了章节名的 txt |
| 章节之间空一行 | 开 | 关掉后章与章之间只隔一个换行 |

四种组合：

| 加标题 | 空行 | 结果 |
|---|---|---|
| 开 | 开 | 章名 + 空行 + 正文；章与章之间空一行（默认） |
| 关 | 开 | 只有正文；章与章之间空一行 |
| 开 | 关 | 章名紧跟正文；章与章之间只隔一个换行 |
| 关 | 关 | 只有正文；章与章之间只隔一个换行 |

另外：

- 关掉「加标题」时，「正文首行与文件名重复时去掉一行」会自动禁用（没有标题，就无所谓去重）；
- 正文首尾的空白会被裁掉，**正文内部一个字都不动**；
- 如果正文第一行本身就是章节名（很多现成 txt 会这样），勾选「正文首行与文件名重复时去掉一行」即可避免出现两遍。

## 三、目录结构

```
TextForever-Modern/
├─ index.html            页面骨架：顶栏、文件列表、输出设置、预览
├─ 启动.bat              双击启动本地服务并打开页面（纯 ASCII 提示，需要 Python 3）
├─ 启动_GBK.bat          同上，中文提示（GBK 编码；在 UTF-8 编辑器里打开会乱码）
├─ 启动_GBK.txt          GBK 版的可读源文件（UTF-8）；改完需重新转成 GBK
├─ app/
│  ├─ styles.css         全部样式（手写，无框架、无外部字体）
│  ├─ encoding.js        编码检测 / 解码 / 导出编码
│  ├─ sorter.js          章节号解析 + 排序（核心逻辑）
│  ├─ files.js           选文件夹、拖放、递归收集 txt
│  ├─ merger.js          拼装最终文本
│  ├─ ui.js              把状态画到页面上
│  └─ main.js            应用状态与流程编排
├─ tests/
│  └─ selftest.js        纯逻辑自测（开发用，网页不加载它）
└─ README.md             本文件
```

> ⚠️ 维护提示：bat 的编码规则是「**要么纯 ASCII（推荐），要么 GBK（cp936）+ CRLF，绝不能是带中文的 UTF-8**」。`cmd` 按系统代码页读批处理、**不认文件里的编码声明**：UTF-8 中文会被当成 GBK 误读，导致整行拆断、报"不是内部或外部命令"（2026-11-19 实测）。`启动_GBK.bat` 的可读源是 `启动_GBK.txt`，改完要重新转码。

## 四、依赖

**第三方依赖：0。** 没有 npm、没有 CDN、没有打包步骤、没有字体文件。

只用浏览器自带的能力：

| 能力 | 用在哪 | 说明 |
|---|---|---|
| File API / `webkitdirectory` | 选文件夹、读文件 | 标准能力，主流浏览器都有 |
| `webkitGetAsEntry` | 拖放时递归子目录 | Chromium / Firefox 支持；不支持时退化为普通文件多选 |
| `TextDecoder` | 读文件、探测编码 | 内置 UTF-8 / GB18030 / UTF-16 解码器 |
| `TextEncoder` | 写出 UTF-8 | 浏览器只提供 UTF-8 编码，GB18030 见下文 |
| `Intl.Collator` | 中文拼音排序 | 用系统自带的中文排序规则，不内置字典 |
| `Blob` / `URL` | 生成下载文件 | — |
| `showSaveFilePicker`（可选） | 让"保存"弹出系统对话框 | Chromium 支持；不支持时自动退回浏览器下载 |

**运行条件**：任意现代浏览器。不需要联网，不需要管理员权限，不写注册表。
可选的 `启动.bat` 需要 **Python 3**（只调用它自带的标准库 `http.server`，不安装任何包）。

## 五、各模块怎么实现的

| 文件 | 职责 | 实现方式与关键点 |
|---|---|---|
| `index.html` | 页面结构 | 全部用**经典脚本**（`<script src>`，不是 ES Module）。原因：双击打开是 `file://` 协议，ES Module 会被浏览器的跨域策略拦住，改用经典脚本才能真正"双击即用" |
| `styles.css` | 视觉 | 手写 CSS 变量 + 卡片布局；无框架；窄屏下隐藏次要列 |
| `encoding.js` | 编码 | 读：BOM → UTF-8 严格校验 → GB18030 严格校验 → 兜底容错 UTF-8。写：UTF-8 / 加 BOM / GB18030 |
| `sorter.js` | 排序 | 正则提取「第X卷/章/回/节/话/篇」与数字前缀；中文数字用状态机转数值；比较时用 `Intl.Collator('zh-Hans-CN-u-co-pinyin')` 做拼音兜底 |
| `files.js` | 收集文件 | `<input webkitdirectory>` 拿整目录；拖放走 `DataTransferItem.webkitGetAsEntry()` 递归遍历目录；自己拼相对路径用于区分同名文件 |
| `merger.js` | 拼接 | 统一换行 → 裁首尾空白 → 可选去掉重复标题行 → 按「加标题 / 空行」两个开关插入章名与空白 → 逐章拼接 |
| `ui.js` | 渲染 | 原生 DOM 操作：表格行、编码下拉框、预览区、提示条；不保存业务状态 |
| `main.js` | 编排 | 单一 `state` 对象保存文件列表；所有操作（加载、排序、手动移动、换编码、导出）都只改 `state` 再调用 `refresh()` |

### 为什么排序不能只按拼音

`第十章` 的拼音是 *di shi zhang*，`第二章` 是 *di er zhang*；按字母顺序，**"第"之后比 s 和 e，第十章会跑到第二章前面**。所以主键必须是数值化的章节号，拼音只用于"没有章节号"或"章节号相同"的情况。

## 六、排序规则

比较顺序（从高到低）：

| 优先级 | 键 | 规则 |
|---|---|---|
| 1 | 卷号 | `第X卷 / 部 / 集` 中的数字；没有卷号按 0 处理 |
| 2 | 章节号 | `第X章 / 回 / 节 / 话 / 篇`；没有就用文件名开头的数字（`001`、`12-3`、`7.`）；再没有就用 `chapter 7` 这种写法 |
| 3 | 特殊名 | 没有章节号时：`序` / `序章` / `序言` / `楔子` / `引子` / `前言` / `开篇` / `卷首` → 排最前（-1）；`后记` / `尾声` / `番外` / `附录` / `外传` / `作者的话` → 排最后 |
| 4 | 文字部分 | `Intl.Collator` 拼音比较，数字按数值（`2 < 10`） |
| 5 | 数字部分 | 中文 / 阿拉伯数字一律按**数值**比：`其零 < 其一 < 其二 < 其三`、`十 < 十一 < 二十` |
| 6 | 兜底 | 文件名原样比较，保证结果唯一、可复现 |

> 第 5 条是必须的：中文数字若按拼音比，`零(ling)`、`二(er)`、`三(san)`、`一(yi)` 会乱序。所以比较时先把文件名切成「文字块 / 数字块」，文字块按拼音、数字块按数值。

支持的中文数字：`零〇一二三四五六七八九十百千万亿两`，以及大写 `壹贰叁肆伍陆柒捌玖拾佰仟萬`；全角数字 `０１２` 也认。

排序方式的三个选项：**章节自然序**（推荐）、**拼音**、**文件名**；勾「倒序」整体反转。

## 七、编码是怎么判断的

### 读（每个文件独立判断）

1. 开头是 `EF BB BF` → UTF-8 (BOM)，剥掉 BOM 再解；
2. 开头是 `FF FE` / `FE FF` → UTF-16 LE / BE；
3. 用严格模式按 UTF-8 解一次，**能解通就是 UTF-8**；
4. 再用严格模式按 GB18030 解一次，能解通就是 GB18030；
5. 都不行 → 兜底容错 UTF-8（可能出乱码，但不会崩）。

列表里显示的是**检测结果**；判断错了就在该行的下拉框里手动指定，会立刻重新解码并刷新预览。

### 写

| 选项 | 字节 | 适合 |
|---|---|---|
| UTF-8（无 BOM） | 直接是 UTF-8 | 现代阅读器、手机、VS Code（默认） |
| UTF-8（带 BOM） | 前面加 `EF BB BF` | 老版 Windows 记事本、部分旧阅读软件 |
| GB18030 | 双字节中文 | 只认国标编码的老国产软件 |

**GB18030 是怎么写出来的**：浏览器只提供 UTF-8 编码器，没有 GB18030 编码器。
这里的做法是「反向建表」——把 GB18030 所有合法的双字节组合（约 2.4 万个）逐个用 `TextDecoder` 解出来，
反过来得到 **字符 → 字节** 的映射，第一次导出 GB18030 时构建（约几十到几百毫秒），之后复用。

> 局限：只覆盖 GB18030 的**双字节区**（即 GBK 范围的常用汉字）。emoji、以及四字节区的生僻扩展字无法表示，
> 会被替换成 `?`，并弹提示告诉你替换了多少个。要保留这些字，请选 UTF-8。

## 八、便携性（换设备怎么用）

- **整个 `TextForever-Modern` 文件夹就是全部**：复制 / 压缩 / 发给自己，解压后双击 `index.html`。
- 不依赖绝对路径，不写任何配置文件，不产生缓存目录（浏览器自身的缓存除外）。
- Windows、macOS、Linux 通用——只要有现代浏览器。
- 换到**没有 Python** 的机器：直接双击 `index.html`，用「选择文件夹」加载，其余功能完全一样。
- 想放到 U 盘里带着走也完全可以。

**只有跑自测才需要 Node**（`node tests\selftest.js`，Node 18+）；日常使用不需要，`tests/` 删掉也不影响网页。

## 九、已知局限

1. **文件选择 / 拖放 / 保存对话框尚无自动化验证**：核心逻辑有自测覆盖（`tests/selftest.js`），并用真实章节目录跑通排序与合并（`tests/merge-dir.js`）；页面渲染、空状态、排序控件已在浏览器实测通过（2026-11-19）。系统文件选择框无法被自动化工具驱动，需要人工点一次。
2. `showSaveFilePicker` 不可用时（如 Firefox / Safari），导出走浏览器下载，文件会落在默认下载目录。
3. **Tabbit 在 `file://` 下拖放不可用**（2026-11-19 实测）：同一页面改用 `http://127.0.0.1` 后拖放正常。双击 `index.html` 时请用「选择文件夹」，或改用 `启动.bat`；某些拖放来源还会让 `webkitGetAsEntry()` 抛出 URI 错误，代码已做逐项兜底。
4. 受浏览器内存限制：几百 MB 的超大合并不现实；普通小说（几 MB ~ 几十 MB）没有问题。
5. 输出里的章节标题只取**文件名**，不含子目录名——不同子目录下的同章节名会重名，需要自己改名区分。
6. GB18030 导出不支持 emoji 与四字节区字符（见第七节）。

## 十、自测

```bash
node tests\selftest.js
```

覆盖：中文数字解析、章节号识别、自然序 / 倒序、合并格式与标题去重、UTF-8 / GB18030 / BOM 检测与解码、GB18030 反向建表编码。

用真实章节目录验证（只读，不写任何文件）：

```bash
node tests\merge-dir.js "D:\某本小说\章节目录"
```

会打印识别出的章节顺序、重复章节号提示、合并后的字符数与开头 / 结尾片段。它加载的就是 `app/` 里网页用的同一份模块。
